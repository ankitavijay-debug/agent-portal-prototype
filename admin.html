What agents may do, who approves, and where the limits sit
Signed in as admin (tok-admin)

1. Start from a posture

Pick a preset as a baseline, then adjust. Presets only change tiers, approvers and thresholds, never agent scopes. You can undo any change from the change log.

2. Classify every action (the capability manifest)

Score each action on reversibility, money, customer-visible impact and data sensitivity, then set the tier. Rule of thumb: reversible and internal = tier 1; irreversible or money = tier 2; identity or contact data = tier 3 with step-up; exceptions to policy = tier 4 (a human enterprise agent first, then the customer).

3. Scope each agent (least privilege)

A surface agent such as Claude or ChatGPT gets only what a conversation needs. Background agents get what the goal plan needs. Anything unticked is denied and logged.

4. Set thresholds

Each threshold shows a recommended starting value and how to tune it from real data. Start tight; loosen only with evidence.

7. Personal Agent Protocol (Poppy): what personal agents see and who may connect

The portal publishes a poppy.json and a tasks endpoint from this policy. Excluded tasks are things you do not offer through any interface (agent, API or website). Limits that depend on the account, such as the $100 fee limit or the goal budget, are not exclusions: they return errors.
